# Public deployment

The public backend differs from the local application: users upload chat and Memory data to the server. The browser UI discloses that fact. The backend listens only on loopback, uses a 20 MB input limit and a 64 MB expanded ZIP limit, keeps request bodies and conversion output in memory, accepts the configured HTTPS origin, rejects the shutdown endpoint, and limits active backend connections. The sample nginx configuration disables access logs and proxy request buffering, limits request rates and connections, and terminates TLS. The sample systemd unit limits memory and CPU and applies process isolation.

These measures reduce risk; they cannot guarantee security or prevent all denial-of-service attacks. TLS, certificate renewal, host updates, backups, resource monitoring, firewall and provider-level protection need independent administration. The nginx configuration must only be loaded after its certificate exists, and must be reviewed against the host's existing services. Public source and documentation should be served from `/source/`. The sample assumes a specific domain and is not a one-command installer.
